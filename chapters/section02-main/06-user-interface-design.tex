\chapter{User Interface and Usability}
\label{user_interface_and_usability}

This chapter presents the design and development of the SafeVision user interface. The interface was designed to support a human-in-the-loop workflow, where machine learning-based detection is combined with manual user verification and adjustment. Since the system is intended to extend Safe Media AI's existing redaction capabilities to visual media, the design also considered familiarity with the existing Safe Media AI interface in order to reduce the learning curve for users already accustomed to that platform. The chapter focuses on how the interface supports efficient interaction with detection results, provides clear visual feedback, and allows users to inspect, refine, and control automated outputs before redaction is applied.

\section{Design Methodology and Principles}

The development of the user interface followed an iterative design process, where layout, interaction patterns, and workflow structure were gradually refined throughout the project. Instead of defining the complete interface at the beginning, design decisions were adjusted as functionality evolved and new usability needs were identified. Iterative design is widely recommended in user interface development because it allows teams to evaluate design decisions and improve solutions based on testing and practical experience \cite{hartson2012ux}. This approach allowed the design to evolve alongside the technical implementation while maintaining focus on usability and user control.

\methodheading{Iterative and Agile Design Process}

The project followed an agile development approach where design and implementation were carried out in parallel. As new features were introduced, the interface was continuously adjusted to support the expanding functionality of the system. This was important because SafeVision evolved from a basic image redaction prototype into a more complete tool supporting image and video workflows, detection configuration, manual refinement, and multiple redaction methods.

This approach aligns with Agile UX practices, where interface decisions are refined through incremental improvements rather than finalized early in development \cite{gothelf2022leanux}. Agile frameworks such as Scrum also emphasize iterative cycles that allow continuous refinement of both technical solutions and interface design \cite{schwaber2020scrum}.

The design process began with wireframes created in Figma to explore layout and interaction flows before implementation. Wireframing allows designers to quickly test ideas before committing to development \cite{hartson2012ux}. These wireframes were used to define the main workflow, including uploading files, running detection, reviewing detection results, and applying redaction.

A functional prototype was then implemented to evaluate interaction patterns and identify usability issues in a practical environment. After the prototype stage, the design was refined into a minimum viable product (MVP), where core system functionality was integrated into the interface. The interface was also influenced by Safe Media AI's existing system, allowing users familiar with that platform to encounter recognizable layout structures and interaction patterns. This helped support consistency and reduced the learning curve for potential users.

\methodheading{Core Design Principles}

Several design principles guided the development of the interface: simplicity, user control, visual feedback, and consistency. These principles were selected because SafeVision combines automated machine learning output with manual user verification, making it important that the interface remains understandable, predictable, and easy to control.

Simplicity was prioritized to reduce cognitive load and allow users to focus on identifying and redacting sensitive information \cite{norman2013design}. The interface therefore emphasizes essential functionality while avoiding unnecessary complexity. This was especially important because users must inspect visual content carefully and should not be distracted by unrelated interface elements.

User control over automated processes was also central. Since detection is performed by machine learning models, users must be able to verify, adjust, and override automated results when necessary \cite{hartson2012ux}. The interface supports this through manual highlighting, adjustment of detection settings, removal of incorrect detections, and customization of redaction methods.

Visual feedback was prioritized to help users understand system state and detection outcomes \cite{norman2013design}. Detection results are displayed directly on the media using labelled bounding boxes, enabling immediate interpretation of what the system has identified. Progress indicators and visible processing states further help users understand when the system is working.

Consistency across components improves usability and learnability \cite{nielsen2020progressive}. Toolbars, panels, and controls follow predictable patterns, making the interface easier to navigate. In addition, alignment with familiar structures from Safe Media AI's existing system supports recognition for users already accustomed to that platform, while still allowing SafeVision to introduce functionality specific to visual media redaction.

\section{Interface Design and Components}

The final SafeVision interface is the result of the design process described earlier in this chapter and documented in greater detail in Appendix~\ref{app:depth_ui_ux}. This section focuses on the final interface structure and how its components support the redaction workflow. The design applies the principles of simplicity, user control, visual feedback, and consistency by keeping upload, identification, verification, manual adjustment, and redaction within one main workspace.

The initial state of the interface is intentionally minimal, as shown in Figure~\ref{fig:final_empty_state}. Before files are uploaded, the user is presented with a clear upload action and an empty file panel. This supports simplicity by avoiding unnecessary controls before they become relevant. Once files are uploaded, the interface expands into the full editing workspace with a file panel, toolbar, central media viewer, and configuration panels.

The left file panel provides an overview of uploaded images and videos. Each file item displays relevant information such as file name, file type, file size, selection state, and deletion control. During longer operations, each file can also display an individual progress indicator, as shown in Figure~\ref{fig:file_progress}. This design choice was introduced to improve visual feedback and system state awareness. Since SafeVision may process several files, users need to understand which file is selected, which task is running, and how far the processing has progressed. This directly supports the principle of visual feedback discussed earlier and helps reduce uncertainty during identification and redaction.

The central workspace is the main interaction area of the application. Uploaded images and videos are displayed in the middle of the screen, keeping the user's focus on the visual content being processed. This supports the goal of reducing cognitive load, as users can inspect detection results directly on the media rather than comparing separate lists or external outputs. When identification is completed, detected regions are displayed as labelled bounding boxes directly on top of the image or video frame, as shown in Figures~\ref{fig:image_detection_results} and~\ref{fig:video_detection_results}. This is essential for the human-in-the-loop workflow, since users must be able to verify automated results before redaction is applied.

The use of overlays and labelled bounding boxes reflects the principle of visual feedback \cite{norman2013design}. Detection results are shown where the sensitive content appears, making the system output immediately understandable. This allows users to quickly assess whether the detected regions are correct, remove false positives, or add missing regions manually. Since machine learning models may produce inaccurate or incomplete detections, the interface does not treat automated results as final. Instead, it supports user control by allowing inspection and correction before redaction is performed \cite{hartson2012ux}.

The top toolbar contains the primary workflow actions, including undo, redo, download, print, identification, redaction, manual highlighting, annotation visibility, zoom controls, and clearing of highlights. These controls are placed consistently above the workspace so that the main workflow remains visible and predictable. During the final design iteration, the earlier label ``AI mission'' was renamed to ``Identify''. This change improved terminology by describing the action from the user's perspective rather than from the system's internal logic. The ordering of the toolbar actions also reflects the intended task sequence: identify sensitive regions, inspect and adjust them, and then apply redaction.

The side panel contains secondary and advanced settings, as shown in Figure~\ref{fig:options_panel_components}. Users can configure redaction mode, segmentation, adaptive scaling, multi-orientation detection, detection filters, scale, and video detection rate. These controls are important for flexibility, but they are not required for every basic workflow. Placing these settings in a dedicated side panel supports progressive disclosure, where advanced functionality remains available without overwhelming the main workspace \cite{nielsen2020progressive}. This balances simplicity for new users with control for more advanced users.

Detection filters allow users to control which categories should be identified, such as faces, text, or vehicles. This supports user control over automated processing and helps reduce unnecessary visual clutter. Different images and videos may require different redaction priorities, so allowing users to configure detection categories makes the system more adaptable to specific use cases. This also supports the broader design goal of keeping automated detection helpful without removing user responsibility from the redaction process.

The highlight style panel, shown in Figure~\ref{fig:highlight_styles}, supports customization of how detected and manually marked regions are displayed. Users can adjust label visibility, colors, fill opacity, stroke opacity, stroke width, and category-specific styles. This is especially important because SafeVision may be used on visually complex images or videos where a single highlight style may not always be readable. Customizable highlighting therefore supports both visual feedback and accessibility, especially during detailed inspection tasks.

The user preferences panel provides additional flexibility through appearance settings, export format, and keyboard shortcuts, as shown in Figure~\ref{fig:user_preferences}. Dark and light modes allow the interface to be adapted to different working conditions, while shortcut customization supports faster interaction for experienced users. At the same time, all important actions remain available through visible interface controls, making the system usable for users who do not rely on shortcuts. This supports both accessibility and learnability.

Video support extends the same workspace principles to temporal media. As shown in Figure~\ref{fig:video_workspace}, videos are displayed in the central viewer with playback controls, while the surrounding interface remains consistent with the image workflow. After identification, detected regions can be shown on the video frame, as illustrated in Figure~\ref{fig:video_detection_results}. This consistency helps users transfer knowledge from image redaction to video redaction, reducing the learning curve. At the same time, video introduces additional complexity because detections must be interpreted across frames, making clear visual feedback and playback control especially important.

Overall, the final interface applies the design principles described in the previous subsections to the practical needs of SafeVision. Simplicity is reflected in the single workspace layout, user control is supported through editable detections and configurable settings, visual feedback is provided through overlays and progress indicators, and consistency is maintained through predictable toolbar and panel structures. The resulting design supports SafeVision's main goal: combining automated detection with user guided refinement so that sensitive visual content can be identified, verified, and redacted in an efficient and controlled workflow.
