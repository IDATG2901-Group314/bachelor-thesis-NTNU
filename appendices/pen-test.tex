    \centering

    \caption{Payload inspection for the \texttt{/redact} request}
\end{figure}

\noindent \textbf{Test case:} Sensitive data exposure in browser network traffic

\noindent \textbf{What was checked:} Requests and responses in the browser DevTools Network tab during normal \texttt{detect} and \texttt{redact} operations.

\noindent \textbf{Expected result:} Sensitive content should be sent only as needed and not exposed unnecessarily in URLs or cached fields.

\noindent \textbf{Actual result:} The inspected network traffic showed that operational parameters such as \texttt{types}, \texttt{scale}, and \texttt{use\_preprocess} were included in the query string for \texttt{/detect}. The uploaded image itself was sent as binary form-data in the request body rather than in the URL. For \texttt{/redact}, the request body contained the binary file, the selected redaction method, and detection results used for redaction. These detection results were visible in the request body, but not in the URL.

\noindent \textbf{Assessment:} No unnecessary exposure of sensitive data in request URLs was observed. Image content was transmitted as binary form-data, while detection metadata appeared in the \texttt{results} body field only where needed for the redaction workflow.

\section*{Test 18 --- CORS behavior from browser}
\label{appsec:pen_test_18}

\noindent \textbf{Test case:} CORS restriction review

\noindent \textbf{What was checked:} Browser request behavior during normal frontend use, including whether requests completed without unexpected CORS errors, and whether the backend configuration appeared to restrict allowed origins.

\noindent \textbf{Expected result:} Only expected frontend origins should be allowed.

\noindent \textbf{Actual result:} During normal browser use, the frontend requests completed without visible CORS errors in DevTools. No indication was observed that arbitrary origins were being allowed from the browser-facing workflow. In addition, the backend implementation shown in Listing~\ref{lst:fastapi_routing} uses a defined \texttt{ALLOWED\_ORIGINS} list rather than a wildcard \texttt{*}, which indicates a more restrictive CORS policy.

\noindent \textbf{Assessment:} CORS appears restricted to expected frontend origins. This is supported both by normal browser behavior and by the backend implementation in Listing~\ref{lst:fastapi_routing}, which uses an origin allowlist rather than a wildcard policy. However, this was not a dedicated cross-origin bypass test.
